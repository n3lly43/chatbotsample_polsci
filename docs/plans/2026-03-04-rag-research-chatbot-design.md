# RAG Research Chatbot Template — Design Document

**Date:** 2026-03-04
**Author:** Jie Lian
**Status:** Approved

## 1. Overview

A reusable, open-source chatbot template that lets users build a research assistant grounded in their own local knowledge base. Users download the template from GitHub, provide an API key, drop their documents into a `knowledge_base/` folder, and get a citation-verified chatbot with strong anti-hallucination guardrails.

**Target audience:** Both academics (primary) and general users with domain-specific documents.

**Distribution:** GitHub template repository with a quickstart setup wizard.

## 2. Requirements Summary

| Decision | Choice |
|---|---|
| Audience | General-purpose, marketed to academics |
| Interface | CLI + Web UI (Streamlit) |
| Web search | Pluggable (Semantic Scholar default, swappable/disable) |
| LLM providers | OpenAI + Anthropic + Google Gemini |
| Model selection | Live fetch from provider API, fallback to defaults |
| Configuration | Interactive setup wizard + config.yaml |
| Embeddings | Free local default (ChromaDB), OpenAI upgrade option |
| Distribution | GitHub template repo + quickstart script |
| Setup | pip install primary, Docker optional |
| Anti-hallucination | #1 priority — 6-layer verification stack |

### 4.2 Registry Pattern

LLM providers, search backends, and file readers each use a simple dict registry in their `__init__.py`:

```python
# src/llm/__init__.py
PROVIDERS = {
    "openai": openai_generate,
    "anthropic": anthropic_generate,
    "gemini": gemini_generate,
}

def generate(system_prompt, user_message, provider=None):
    provider = provider or config.LLM_PROVIDER
    if provider not in PROVIDERS:
        raise ValueError(f"Unknown provider: {provider}")
    return PROVIDERS[provider](system_prompt, user_message)
```

Same pattern for `src/search/__init__.py` (BACKENDS dict) and `src/readers/__init__.py` (READERS dict mapping extensions to reader functions).

Adding a new provider/format = write one file + add one line to the registry.

### 4.3 Data Flow

```
User query
    |
    v
understand_query(query, history, cfg)
    |
    ├── [if CLARIFY: ask user, get answer, re-call understand_query]
    |
    └── [if SEARCH: produces search_query + display_query]
            |
            v
retrieve(search_query) --> ChromaDB vector search (ALWAYS runs first)
                       --> Web search (optional, if enabled)
    |
    v
build_prompt() --> inject context + anti-hallucination guardrails
    |              (adapts to 4 scenarios: local+web, local-only,
    |               web-only, no-sources)
    v
verify_and_respond(display_query, results) --> LLM provider (from registry)
    |
    v
verify() --> 6-layer anti-hallucination stack
    |
    v
Display cited response with reference list
```

- `search_query`: keyword-optimized for vector retrieval
- `display_query`: clear natural-language question for response LLM (incorporates clarification)
- `original_query`: raw user input, kept for reference/logging

## 5. Retrieval Strategy

### 5.1 Web Search Toggle

- **Setup wizard:** asks user whether to enable web search (Step 5)
- **CLI runtime:** `/websearch on|off` command
- **Web UI runtime:** sidebar toggle switch

### 5.2 Priority Logic (Non-Negotiable)

Local knowledge base is ALWAYS the primary authority, regardless of web search setting.

| Scenario | Behavior |
|---|---|
| Local + Web | Local sources = PRIMARY. Web = supplementary. Web never overrides local. |
| Local only | Only local sources used. |
| Web only (no local docs ingested) | Web results used with warning: "No local knowledge base found." |
| No sources at all | LLM is NOT called. Hardcoded refusal returned. |

### 5.3 Chunk ID Anchoring

Each retrieved chunk gets a unique anchor ID in the context block:

```
[CHUNK-LOCAL-001] From: Chenoweth_2011.pdf (p.23)
  Path: knowledge_base/NAVCO 2.0/Chenoweth_2011.pdf
  "Nonviolent campaigns succeeded 53% of the time..."

[CHUNK-WEB-001] From: Nepstad (2011). "Nonviolent Revolutions"
  URL: https://doi.org/10.xxxx/yyyy
  Abstract: ...
```

The LLM must cite by these anchor IDs. The verifier checks that every citation maps to a real chunk.

## 6. Anti-Hallucination System (6-Layer Stack)

This is the most critical part of the design. Anti-hallucination is the #1 priority.

### Layer 0: No-Context Early Exit

If retrieval returns zero local chunks AND zero web results, the LLM is **never called**. A hardcoded Python string is returned:

```
"I don't have any information on this topic in my knowledge base.
No relevant local documents or web sources were found.
Please try a different question, or add relevant materials to
the knowledge_base/ folder and run ingestion again."
```

Zero hallucination risk — no LLM involvement.

### Layer 1: System Prompt — Hard Refusal of Memory

The system prompt contains an absolute, non-negotiable directive:

```
## ABSOLUTE RULE — ZERO TOLERANCE FOR HALLUCINATION

You are a retrieval-only assistant. You MUST:
- ONLY use information from the PROVIDED CONTEXT below.
- NEVER use your training data, general knowledge, or memory to answer.
- NEVER infer, guess, or "fill in gaps" with plausible-sounding information.
- If a user asks something not covered by the context: REFUSE to answer.
  Say: "I don't have information on this in my knowledge base."
- Do NOT say "Based on my knowledge..." or "Generally speaking..." —
  these phrases indicate you are drawing from memory, not sources.

There are NO exceptions. An incomplete answer is always better than
a fabricated one. Silence is always better than a guess.
```

Additional Layer 1 directives:
- **Direct quote anchoring:** For key findings, include a direct quote from the source material. If you cannot find a direct quote to support a claim, do NOT make that claim.
- **Response length guidance:** Response length should generally be proportional to available evidence. If only 1-2 sources, keep the answer focused and concise. Brief synthesis is allowed, but do not pad beyond what sources support.

### Layer 2: Response Length Cap (Soft)

Dynamically adjusts `max_tokens` based on retrieved context size:

```python
context_chars = len(combined_context)
if context_chars < 500:
    max_tokens = 1024
elif context_chars < 2000:
    max_tokens = 1536
else:
    max_tokens = config.max_tokens  # default 2048
```

This is a soft suggestion, not a hard cutoff. The system prompt also encourages proportional response length.

### Layer 3: LLM Self-Verification Loop

After generation, a second LLM call verifies the response against the provided sources:

**Verification prompt:**

```
Verify the following response against ONLY the provided sources.

For each factual claim, check:
1. Is this claim directly supported by a source in the context?
2. Is the citation correct (right source, right page/URL)?
3. Is any information added that does NOT appear in the context?
4. Do direct quotes actually appear in the cited source chunk?
5. Are any claims flagged by the advisory warnings below unsupported?

Advisory flags from automated checks:
{phrase_flags}
{similarity_flags}

Report as JSON:
{
  "errors": [
    {"claim": "...", "issue": "not found in sources | wrong citation | from model memory"},
  ],
  "error_count": <int>,
  "pass": true | false
}
```

**Iterative correction logic:**

```
Generate response
    |
    v
Verify against sources
    |
    ├── pass=true --> Show to user
    |
    └── pass=false
        ├── ≤2 errors: Correct once --> Re-verify
        |       ├── pass=true --> Show to user
        |       └── pass=false --> REFUSE to answer
        |
        └── >2 errors: Correct --> Re-verify --> still errors?
                --> Correct again (loop until clean, max 3 iterations)
                --> Still errors after max? --> REFUSE to answer
```

**Refusal message:**

```
"I was unable to produce a verified answer from my knowledge base.
Please try rephrasing your question."
```

**9-point verifier checklist:**

1. Every factual claim has at least one `[N]` citation
2. Every `[N]` in text appears in the reference list
3. Every reference list entry is used in the text
4. Local source paths match real chunks from context
5. Web source URLs/DOIs match search backend results
6. Direct quotes actually appear in the cited source chunk
7. No banned phrases without adjacent citations (from Layer 5 flags)
8. Claims flagged by semantic similarity are re-examined (from Layer 4 flags)
9. No information added that doesn't appear in context

### Layer 4: Semantic Similarity Post-Check

A non-LLM verification step using embeddings:

```python
claim_embedding = embed(claim_text)
cited_chunk_embedding = embed(cited_source_chunk)
similarity = cosine_similarity(claim_embedding, cited_chunk_embedding)

if similarity < 0.6:
    flag_as_advisory(claim)  # passed to Layer 3 as context
```

This is a mathematical check — no LLM judgment involved. Catches cases where the LLM cites a source but says something the source doesn't support.

### Layer 5: Soft Phrase Warning Filter

Scans for phrases that may indicate the model is drawing from memory. These are **advisory flags**, not automatic errors:

```python
WARNING_PHRASES = [
    "based on my knowledge",
    "generally speaking",
    "it is well known",
    "as we all know",
    "it is widely accepted",
    "common understanding suggests",
    "from what I know",
    "I recall that",
]
```

Flagged phrases are passed to the Layer 3 verifier as advisory context: "pay extra attention to these sections." A flagged phrase followed by a proper citation `[N]` passes fine. Only if the section genuinely lacks source support does it become an error through normal verification.

### Execution Order

```
User query
    |
    v
Layer 0: No-context early exit
    | (zero sources --> hardcoded refusal, STOP, LLM never called)
    v
Layer 2: Set soft max_tokens cap based on context size
    |
    v
[Generate response from LLM]
    |
    v
Layer 5: Soft phrase warning scan       <-- cheapest, no API cost
    | (advisory flags)
    v
Layer 4: Semantic similarity check      <-- embedding cost only
    | (advisory flags)
    v
Layer 3: LLM self-verification          <-- most expensive
    | (receives Layer 4+5 flags as context)
    | (iterative correction if errors found)
    |
    ├── PASS --> Show to user
    └── FAIL after max iterations --> REFUSE to answer
```

### Cost Configuration

```yaml
verification:
  enabled: true
  max_iterations: 3
  strict_mode: true   # if true, refuse on any remaining error
                      # if false, show answer with warning
```

## 7. Citation & Reference Format

### 7.1 Inline Citations (Endnote Style)

Every factual claim gets a bracketed endnote number:

```
The success rate of nonviolent campaigns was approximately twice that
of violent insurgencies between 1900 and 2006. [1] Economic boycotts
were among the most frequently employed tactics. [2][3]
```

### 7.2 Direct Quote Anchoring

Key findings include a direct quote from the source:

```
As stated in [1]: "nonviolent campaigns succeeded 53% of the time
compared to 26% for violent insurgencies."
```

### 7.3 Reference List

Every response ends with a structured reference list:

```
## References

**Local Sources (Primary):**
[1] Chenoweth_Stephan_2011.pdf (p. 23)
    -- knowledge_base/NAVCO 2.0/Chenoweth_Stephan_2011.pdf
[2] NAVCO2JPRcodebook2013.pdf (p. 7)
    -- knowledge_base/NAVCO 2.0/NAVCO2JPRcodebook2013.pdf

**Web Sources (Supplementary):**
[3] Chenoweth, E. & Stephan, M. (2011). "Why Civil Resistance Works."
    DOI: https://doi.org/10.7312/chen15682
```

### 7.4 Format Rules

| Element | Local Source | Web Source |
|---|---|---|
| Identifier | `[N]` endnote | `[N]` endnote |
| Name | Original filename | Author (Year). "Title" |
| Location | Page/sheet/row range | DOI (preferred) or URL |
| Path | Full relative path from `knowledge_base/` | Full link |
| Priority | **Primary** | **Supplementary** |

## 8. System Prompt Adaptation

The system prompt adapts to four retrieval scenarios:

| Scenario | Prompt Behavior |
|---|---|
| Local + Web | "Local sources are PRIMARY. Web sources are supplementary only. Never let web override local." |
| Local only | "ONLY use the local sources below. Do not add any outside knowledge." |
| Web only (no local docs) | "All sources are from web search. Cite every claim with URL. State clearly you have no curated local sources." |
| No sources | LLM is NOT called. Hardcoded refusal. |

Each provider exposes a `list_models(api_key)` function that calls the provider's API to get available models. If the API call fails (no internet, invalid key), a small hardcoded fallback list is used.

## 10. CLI Interface

Rich-powered terminal chatbot.

**Commands:**
- `/quit` — exit
- `/sources` — show sources from last response
- `/ingest` — re-index knowledge_base/
- `/model` — show current model, switch provider/model
- `/websearch on|off` — toggle web search
- `/help` — show help

## 11. Web UI (Streamlit)

### Layout

- **Header:** chatbot name
- **Sidebar:** provider dropdown, model dropdown (updates on provider change), web search toggle, knowledge base stats (files, chunks, last ingestion), re-ingest button
- **Chat area:** message history with markdown rendering
- **Footer:** persistent banner: "All answers sourced from local knowledge base. Web sources are supplementary only."

### Behaviors

- Chat history maintained in session (not persisted across refreshes)
- During verification loop, spinner: "Verifying answer against sources..."
- Model/provider switch is session-only (does not overwrite config.yaml)
