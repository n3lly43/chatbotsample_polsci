# CLAUDE.md — Project Instructions for Claude Code

## Project Overview

**RAG Research Chatbot Template** — A reusable, citation-verified research assistant chatbot grounded in a local knowledge base. Users download the template, provide an API key, drop documents into `knowledge_base/`, and get a chatbot with strong anti-hallucination guardrails.

## Architecture

- **Registry pattern**: LLM providers (`src/llm/`), search backends (`src/search/`), and file readers (`src/readers/`) each use a dict registry in their `__init__.py`. Adding a new provider/format = write one file + add one line to the registry.
- **Ingestion pipeline**: ingest → chunk → embed → store (ChromaDB)
- **Query pipeline**: query understanding → retrieve → generate → verify (6-layer stack)
- **Config**: `config.yaml` (generated by `setup.py` wizard) + `.env` (API keys, gitignored). Env vars override config values.

## Key Design Decisions

### Query Understanding Layer

Pre-retrieval step that uses the LLM to improve retrieval quality:

- **Reformulation**: Rewrites user queries into search-optimized forms (expand abbreviations, add domain keywords, resolve pronouns from conversation history)
- **Clarification**: When a query is genuinely ambiguous (high bar), asks the user ONE clarification question before searching
- **Conversation history**: Uses last N messages (default 6) to resolve follow-up references like "what about 2023?" or "they"
- **Transparency**: Shows the reformulated query to the user (`Searching for: "..."`)
- **Key principle**: Reformulated query is used ONLY for retrieval. The original query is preserved for response generation
- **Graceful degradation**: Falls back to raw query if LLM call fails. Can be disabled via `query_understanding.enabled: false`
- **No anti-hallucination impact**: Operates before retrieval; the 6-layer stack is unchanged

### Anti-Hallucination is Priority #1

The 6-layer verification stack is the core differentiator. Never weaken these guardrails:

- **Layer 0**: No-source early exit — LLM is NEVER called if retrieval returns zero results
- **Layer 1**: System prompt with zero-tolerance hallucination rules
- **Layer 2**: Soft max-token cap proportional to context size
- **Layer 3**: LLM self-verification with iterative correction loop (max 3 iterations)
- **Layer 4**: Term-overlap semantic similarity check (advisory flags)
- **Layer 5**: Warning-phrase scanner (advisory flags)

### Over-Refusal Prevention

The system prompt distinguishes between "no relevant info" (refuse) and "some relevant info" (provide what's available). An incomplete answer grounded in sources is always better than a refusal when relevant chunks exist.

### Citation Format

- Every factual claim must have a numbered endnote like `[1]`, `[2]`, etc.
- Do NOT use `[N]` as a placeholder — always use actual numbers
- Direct quotes (3+ consecutive words from source) must be in quotation marks
- Every response ends with a **References** section split into **Local Sources (Primary)** and **Web Sources (Supplementary)**
- References must show actual file names/paths/page numbers — NOT chunk IDs (CHUNK-LOCAL-001)
- Local knowledge base ALWAYS takes priority over web sources

### Chunk ID Anchoring

- Local chunks: `[CHUNK-LOCAL-NNN]`
- Web chunks: `[CHUNK-WEB-NNN]`
- These IDs appear in the context block for internal anchoring only — they must NOT appear in user-facing references

### Retrieval Strategy

- Uses **distance-threshold retrieval** instead of fixed top_k
- Queries up to `top_k` (default 50) candidates from ChromaDB
- Keeps only chunks with cosine distance below `max_distance` (default 0.55)
- Broad queries get more chunks; narrow queries get fewer — all based on relevance

## Config Field Names (IMPORTANT)

The `config.yaml` must use these exact field names — the codebase reads them with `.get()`:

| Config Path | Read By | Notes |
|---|---|---|
| `paths.vector_db` | `src/ingest.py` | NOT `vector_store` |
| `paths.knowledge_base` | `src/ingest.py` | default `"knowledge_base"` |
| `web_search.backend` | `src/retriever.py` | NOT `provider` |
| `verification.max_iterations` | `src/verifier.py` | NOT `layers` |
| `verification.strict_mode` | `src/verifier.py` | boolean |
| `retrieval.chunk_size` | `src/ingest.py` | default 1000 |
| `retrieval.chunk_overlap` | `src/ingest.py` | default 100 |
| `retrieval.top_k` | `src/retriever.py` | default 50 (candidate pool cap) |
| `retrieval.max_distance` | `src/retriever.py` | default 0.55 (relevance threshold) |
| `embeddings.provider` | `src/ingest.py` | `"local"` or `"openai"` |
| `query_understanding.enabled` | `src/query_engine.py` | default true |
| `query_understanding.max_history` | `src/query_engine.py` | default 6 |
| `query_understanding.max_clarifications` | `app_cli.py`, `app_web.py` | default 1 |

## Testing

- 59 tests across 13 test files

## Code Style

- Python 3.11–3.13 (Python 3.14+ not supported due to ChromaDB/Pydantic compatibility)
- Type hints on public APIs
- No unnecessary abstractions — registry dicts over class hierarchies
- `.get()` with defaults for all config access (graceful degradation)
- Tests use `tmp_path` fixture and `pytest.importorskip` for optional deps

## Git

- **Repo**: `https://github.com/LIANJie-Jason/chatbotsample_api` (private)
- **Branch**: `master`
- Commit style: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `style:`

## Do NOT

- Weaken anti-hallucination guardrails without explicit user approval
- Remove citation requirements from prompts
- Allow the LLM to be called when no sources are retrieved (Layer 0)
- Use `[N]` as a placeholder in prompts — the LLM copies it literally
- Show chunk IDs (CHUNK-LOCAL-001) in user-facing references
- Use direct dict access (`cfg["key"]`) for config — always use `.get()` with defaults
- Change config field names without updating ALL consumers + setup wizard + tests
- Commit `.env` files or API keys
